1. Project Overview
QuantumShield Lab is an interactive web-based laboratory for learning about post-quantum cryptography through discrete mathematics, supported cryptographic operations, and controlled performance experiments.
The problem
Public-key cryptography protects banking, software updates, communications and sensitive records. A sufficiently capable fault-tolerant quantum computer could threaten some widely used public-key systems, including RSA and elliptic-curve cryptography. Post-quantum cryptography (PQC) develops algorithms designed to resist attacks from classical and quantum computers.
The proposed solution
Teach the difference between classical cryptography, quantum cryptography and post-quantum cryptography.
Demonstrate modular arithmetic, number theory, matrices, vectors, lattice intuition, hash functions, probability and complexity.
Use established implementations of standardized algorithms instead of inventing production cryptography.
Measure operation timings and output sizes under controlled conditions.
Save experiment metadata and measurements so results can be reviewed and compared.
IMPORTANTThis project does not claim that current quantum computers can routinely break production RSA, that it creates a new cryptographic algorithm, or that the application itself guarantees security. Treat all planned features as planned until implemented and tested.

Simplified noisy-equation example
b = As + e (mod q)
A is a matrix, s is a secret vector, e is a small error/noise vector, q is a modulus and b is the resulting vector. Recovering secret information from noisy relationships is related to the hard mathematical problems underlying lattice-based cryptography. This is an educational illustration, not the full ML-KEM or ML-DSA specification.
A = [[2, 1],     [1, 3]]s = [1, 2]e = [1, 0]q = 7A @ s = [4, 7]A @ s + e = [5, 7]b = [5 mod 7, 7 mod 7] = [5, 0]
The website can let users change values and observe the result. Label this clearly as an educational demonstration, not a practical attack or a standardized algorithm implementation.

8. Mathematical Demonstrations
A. Modular arithmetic
Allow users to calculate modular addition, multiplication and modular exponentiation. Example: 5^3 mod 7 = 125 mod 7 = 6. Explain each intermediate step.
B. Matrix and noise visualization
# Save as backend/app/math_lab/lattice_demo.pyimport numpy as npdef noisy_linear_demo():    A = np.array([[2, 1], [1, 3]])    secret = np.array([1, 2])    noise = np.array([1, 0])    q = 7    result = (A @ secret + noise) % q    return {        "matrix": A.tolist(),        "secret_vector": secret.tolist(),        "noise_vector": noise.tolist(),        "modulus": q,        "result": result.tolist(),    }if __name__ == "__main__":    print(noisy_linear_demo())
Expected output vector is [5, 0]. This illustrates modular linear algebra only; it is not ML-KEM.
C. Hash demonstration
Accept a test message and display its SHA-256 digest.
Show that a small input change produces a very different digest with overwhelming probability.
Explain that hashing is not encryption and a hash alone is not a signature.
Use a real signature library for signing and verification.
9. Cryptographic Integration
ML-KEM workflow
Generate a key pair.
Use the public key to encapsulate, producing a ciphertext and shared secret.
Use the private key to decapsulate the ciphertext.
Check inside the backend that both shared secrets match.
Record timings and public output sizes without exposing or persisting the shared secret.
Signature workflow
Generate a signing key pair.
Sign a test message with the private key.
Verify the signature using the public key.
Modify the message and verify the original signature against the modified message.
Show verification status; do not display private keys or claim that a signature hides the message.
Read official liboqs/liboqs-python instructions and check which mechanisms are available in the exact build. Do not hand-roll production cryptographic algorithms.

Do not compare unlike operations as if they perform the same task. Report parameter sets, library version, operating environment, warm-up count, repetition count, median, spread and sample count. Separate local execution time from network latency.
from statistics import medianfrom time import perf_counterdef measure(operation, repetitions=100, warmups=5):    for _ in range(warmups):        operation()    durations_ms = []    for _ in range(repetitions):        start = perf_counter()        operation()        durations_ms.append((perf_counter() - start) * 1000)    return {        "repetitions": repetitions,        "median_ms": median(durations_ms),        "min_ms": min(durations_ms),        "max_ms": max(durations_ms),        "samples_ms": durations_ms,    }
This helper measures a callable. Connect it to real operations only after confirming each repeated call is valid and that the intended work is being measured. Record every sample and compute variability. Never fabricate benchmark results.

14. Testing and Security
Mathematical correctness: compare calculations with manually verified examples and test invalid moduli and boundary inputs.
ML-KEM correctness: verify encapsulation and decapsulation yield matching secrets for valid inputs.
Signature correctness: valid signatures should verify; changed messages should fail verification.
Benchmark correctness: sample count should match configuration, durations should be nonnegative and output sizes should come from real outputs.
Input validation: reject malformed requests and unsupported algorithm identifiers.
Privacy: never log or persist private keys, shared secrets or sensitive plaintext.
Resource control: limit request sizes, repetitions and benchmark duration.
Honest claims: using an established library does not independently audit the application or guarantee secure integration.

18. Viva Preparation
What is QuantumShield Lab?
An interactive educational and experimental platform connecting discrete mathematics to standardized post-quantum cryptography and controlled performance analysis.
Why is it a Discrete Mathematics project?
It demonstrates modular arithmetic, number theory, vectors, matrices, lattice intuition, probability, functions and complexity, then uses statistics to analyze measured results.
What does ML-KEM do?
It allows parties to establish a shared secret through key encapsulation. It does not directly encrypt arbitrary documents.
What do ML-DSA and SLH-DSA do?
They are standardized digital-signature algorithms used to sign and verify data. Signatures provide authenticity and integrity, not confidentiality.
Are quantum computers already breaking RSA?
The concern is a sufficiently capable fault-tolerant quantum computer; current quantum computers are not routinely breaking production RSA.
Are you inventing a new algorithm?
No. The contribution is the interactive platform, mathematical demonstrations, experiment framework and comparative analysis.
How will you ensure benchmark fairness?
Use consistent environments, warm-ups, repeated measurements, documented versions and parameter sets, medians and variability.
What makes your contribution useful?
It connects abstract mathematical explanations with supported operations and measurable experimental results.
19. Short Project Pitch
60–90 SECOND PITCHQuantumShield Lab is an interactive web-based laboratory for understanding post-quantum cryptography through discrete mathematics. As sufficiently capable quantum computers could threaten some existing public-key cryptography, our project explores standardized algorithms such as ML-KEM, ML-DSA and SLH-DSA. We connect concepts like modular arithmetic, matrices, lattices, probability and computational complexity to educational demonstrations and established cryptographic implementations. The platform will also measure operation timings and output sizes under controlled conditions, allowing users to explore practical trade-offs rather than relying only on theory. Our goal is to bridge discrete mathematics, cryptographic engineering and experimental analysis in one interactive system.
